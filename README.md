# Комплект AI

Прототип ИИ-помощника для сайта ekt.kz. Он помогает покупателю подобрать
электротехнические товары, проверить наличие, увидеть объяснимые замены и
собрать корзину только после явного подтверждения.

## Статус

Проект команды **Zhigitter** находится в разработке в рамках HackAlem AI.

**Фаза 5 — фото, списки и спецификация.** Работает диалог с OpenAI: поиск по свободному
запросу, уточнение города в следующем сообщении, реальные цены и остатки,
кандидаты на замену с сопоставлением параметров, предупреждение о конфликте
номинала, ответы об оплате и доставке. Базовые ответы доступны на казахском;
карточки и интерфейс пока на русском. Каталог из фазы 2 сохранён отдельной
вкладкой. Панель «Ваш комплект» предлагает варианты со складов, показывает
сумму и несобранные позиции. Корзина сохраняется после явного подтверждения;
цена и остатки повторно проверяются через API. Улучшены desktop и mobile интерфейсы.
Добавлены CV-поиск по фото, чтение PDF/TXT/CSV с проверкой распознанных строк,
копирование спецификации и скачивание CSV из подтверждённой корзины.

Опубликованная версия: **https://komplekt-ai-zhigitter.vercel.app**.

Результаты проверки: [docs/PHASE5_VERIFICATION.md](docs/PHASE5_VERIFICATION.md).
OpenAI подключён серверным ключом; значения секретов в репозитории отсутствуют.

## Технологии

Next.js App Router, React, TypeScript, Tailwind CSS, Lucide. Приложение
размещено на Vercel; база данных для текущего каталога не требуется.

## Локальный запуск

Требуется Node.js 22 или новее. Проверено окружение Node.js 24.

```bash
npm ci
```

Создайте `.env.local` по образцу `.env.example`. Секреты заполняются только
локально или в настройках Vercel и не коммитятся. Стартовая страница работает
без ключей; подробные карточки требуют доступ к API ekt.kz. Настройки:

| Переменная                             | Назначение                                   |
| -------------------------------------- | -------------------------------------------- |
| `OPENAI_API_KEY`                       | API-ключ проекта OpenAI                      |
| `OPENAI_MODEL`                         | Модель, по умолчанию `gpt-4.1-mini`          |
| `OPENAI_VISION_MODEL`                  | Модель для фото, по умолчанию `gpt-4.1`     |
| `EKT_API_BASE_URL`                     | Базовый адрес API каталога                   |
| `EKT_API_USERNAME`, `EKT_API_PASSWORD` | Доступ к API, выданный партнёром             |
| `CART_SIGNING_SECRET`                  | Случайный секрет длиной не менее 32 символов |

```bash
npm run dev
```

Откройте `http://localhost:3000`. Кнопки примеров заполняют запрос; Enter
отправляет, Shift + Enter добавляет строку. Диалог сохраняется при переключении
вкладок приложения, но сбрасывается при перезагрузке страницы.

## Проверки

```bash
npm run lint
npm run typecheck
npm run build
npm test
npm run env:check
```

`env:check` выводит только наличие переменных, без их значений. Он возвращает
ненулевой код при незаполненных настройках, но не проверяет валидность ключей
и не обращается к внешним API.

`GET /api/health` сообщает фазу 3 и наличие настройки AI. Это проверка
работы приложения, а не доступности внешнего API.

## Каталог и актуальность

- Индекс — первые 10 страниц API ekt.kz, 200 реальных товаров. Это ограниченная
  выборка, а не весь каталог. Время снимка показано под списком.
- `npm run catalog:sync` обновляет `data/catalog-index.json` с серверными
  доступами из `.env.local`. После обновления нужна новая публикация приложения.
- `GET /api/catalog?q=027228&page=1` ищет по индексу; 8 товаров на странице.
- `GET /api/catalog/515291` получает подробности у поставщика. Серверный кеш —
  до 30 секунд; `?refresh=1` и кнопка «Обновить» запрашивают данные заново.
- У цены и остатков карточки есть время получения. При недоступности API
  выполняется один автоматический повтор при сетевой ошибке или HTTP 5xx
  (до 12 секунд на попытку), затем показывается ошибка с кнопкой повтора.
- Общий остаток API показан отдельно от городского. Брак, образцы, витрины,
  маркетинг, восстановленные товары и перемещения исключены из городского
  подсчёта. Склады без определённого города не приписываются к Алматы.
- Неизвестные значения остаются неизвестными. API не сообщает сроки доставки
  и резервирование. Сертификаты показываются только при наличии явной ссылки.
- Фото берутся по предоставленным ссылкам ekt.kz. Для отсутствующих или
  недоступных изображений предусмотрена заглушка.
- Данные поставщика могут противоречить друг другу: у 515291 в названии и
  описании 160 А, а в характеристиках 250 А. Поля сохраняются без исправления;
  в чате такое расхождение выделяется предупреждением.

## Как работает чат

`POST /api/chat` принимает `{city, messages:[{role, content}]}`. Ответ содержит
проверенные карточки, источники, сравнения, предупреждения и `cartChanged:false`.

1. OpenAI Responses API (`gpt-4.1-mini`, `store:false`) разбирает намерение,
   выбирает ID из индекса и извлекает количество. Structured Outputs ограничивает
   ID существующими товарами; сервер повторно проверяет результат.
2. Сервер параллельно запрашивает подробности EKT. Цена и остатки не генерируются
   моделью — они выводятся непосредственно из этих ответов.
3. При отсутствии/нехватке позиции или просьбе о замене сервер сравнивает
   кандидатов. Для автоматов и дифзащиты сверяются тип, ток, полюса, утечка,
   отключающая способность, напряжение и характеристика срабатывания в пределах
   имеющихся данных. Для клемм — число проводников и ток. Отсутствующие параметры
   перечисляются явно; полная взаимозаменяемость не заявляется.
4. Конфликт номинального тока между названием/описанием и характеристиками
   блокирует подтверждение совместимости. Другие виды конфликтов пока не
   распознаются автоматически.
5. Условия покупки взяты из [страницы EKT](https://ekt.kz/checkout-delivery/),
   проверенной 23.09.2026. В источнике найдены разные пороги бесплатной доставки;
   прототип не рассчитывает её стоимость и не обещает дату конкретного заказа.

Контекст ограничен последними сообщениями и размером запроса; за раз — до
четырёх основных товаров. История хранится только в памяти вкладки. Запросы
передаются OpenAI; платёжные данные вводить не нужно. Сохранение ответов в
OpenAI отключено параметром `store:false` (это не обещание нулевого хранения
со стороны провайдера). Модель не имеет инструмента изменения корзины.

Есть ограничения размера тела, ролей сообщений, времени запроса и частоты
вызовов. Ограничитель частоты хранится в памяти серверного экземпляра и не
заменяет распределённую защиту. Недоверенные тексты рассматриваются как данные;
проверки инъекций не являются доказательством защиты от всех атак.

Интерфейс — отдельная демонстрационная площадка. Встраивание виджета в реальный
ekt.kz и подключение его корзины в этой фазе не выполнены.

## Фото, списки и экспорт

**«Найти по фото»**: JPEG/PNG/WebP до 15 МБ. Браузер уменьшает фото до 1800px,
сервер проверяет формат и заново кодирует изображение без исходных метаданных.
OpenAI читает маркировку и видимые признаки. Полный прочитанный код сопоставляется
с реальными артикулами; частичная серия показывает несколько вариантов, не
объявляя их точной моделью. В остальных случаях модель предлагает ID только
из выборки каталога. Пользователь выбирает один товар и количество, затем
сервер проверяет его данные EKT. Номинал и количество проводников на фото
могут распознаваться неверно; маркировку и совместимость нужно сверять.
Количество заказа по фотографии автоматически не извлекается.

**«Загрузить список»**: PDF до 5 страниц / 3 МБ, TXT/CSV в UTF-8 до 16 000
символов, либо фотография списка. За раз — до 4 позиций с предупреждением
о пропущенном остатке. Сначала пользователь проверяет и редактирует строки.
После этого сервер сопоставляет их с каталогом без свободной подстановки
моделью: неизвестные и неоднозначные строки явно отмечаются. Счётчик учитывает
исходное количество строк. Большие списки нужно разбивать; Word/XLSX пока нет.

`POST /api/attachments` принимает multipart `{file,mode,city}`. Проверяются
реальные сигнатуры файлов, размер потока, страницы PDF и размер изображения.
Фото/документ передаются OpenAI через Responses API с `store:false`, без Files
API и без сохранения загрузки в приложении. Это не обещание нулевого хранения
у провайдера. Результат ограничен схемой; модель не получает инструмента изменения
корзины. Найденные команды в файле помечаются; это не доказательство защиты от
всех prompt injection. Лимит 8 распознаваний в минуту на IP хранится в памяти
серверного экземпляра, без распределённой гарантии.

**Спецификация**: кнопка копирования текста и `GET /api/cart/export` для CSV
с UTF-8 BOM, разделителем `;`, источниками, датами и предупреждениями.
Экспортируются сохранённые количества и цены на момент подтверждения, без доставки.
Неподтверждённое редактирование количества не попадает в файл. Потенциальные
формулы из текстовых полей CSV нейтрализуются. Базовый казахский в чате сохранён;
новый интерфейс остаётся русским.

Распознавание использует [ввод изображений](https://developers.openai.com/api/docs/guides/images-vision)
и [PDF-вложения](https://developers.openai.com/api/docs/guides/file-inputs) Responses API.

## Предложение и корзина

Для демонстрации: «Нужны 10 штук 027024 в Алматы». При остатке 5 в Алматы
помощник предлагает частичный комплект или 5 местных + 5 с других складов.
Срок доставки не выдумывается. При доступном кандидате на замену выводятся
совпадения, различия и параметры, которые нужно проверить.

- `POST /api/cart/quote` формирует весь будущий состав, не меняя корзину.
- `POST /api/cart/confirm` требует `confirmed:true` и, при наличии предупреждений,
  отдельного ознакомления с условиями. Перед записью заново запрашивает EKT.
- Предложение подписано HMAC, связано с браузерной сессией и текущей версией
  корзины, действует 5 минут. Подмена, чужая сессия и устаревшая версия отклоняются.
  Повтор того же подтверждения не добавляет товары второй раз.
- Изменение цены, складского распределения или условий требует нового предложения.
  Противоречие номинала, неизвестная цена и недостаточный остаток блокируют запись.
- `/cart` показывает сохранённый состав; изменение количества и удаление тоже
  требуют подтверждения. Cookies подписаны, `HttpOnly`, `SameSite=Strict`, в
  production — `Secure`. Ключ подписи находится только на сервере.

Хранение — 7 дней в cookies этого браузера, до 12 строк, без Supabase.
Ссылка `/cart` не является публичной ссылкой на состав и не переносит его на другое
устройство. Это корзина прототипа, без заказа, оплаты и резерва в EKT.
История чата при переходе на отдельную страницу сбрасывается. Для параллельных
подтверждений из нескольких вкладок нет атомарной блокировки: последний ответ
может заменить cookie; для реального магазина требуется серверная база и транзакция.

API smoke test с отдельной тестовой корзиной:

```bash
node scripts/verify-cart.mjs
```

Адрес задаётся переменной `VERIFY_BASE_URL`; по умолчанию `http://127.0.0.1:3000`.

## Размещение

Для Vercel используйте пресет **Next.js**, корневую папку репозитория и команду
сборки `npm run build`. Переменные окружения добавляются отдельно в настройках
проекта. `.env.local` исключён и из Git, и из загрузки файлов в Vercel.

Первое размещение выполнено через Vercel CLI. Автопубликация по push пока
не подключена: Vercel не смог связать репозиторий организации с проектом.
До подключения Git-интеграции обновления публикуются командой
`npx vercel deploy --prod` из привязанного рабочего каталога.

## Источники и границы прототипа

Источник каталога, изображений и остатков — API ekt.kz.
Текущая выборка — 200 товаров. Корзина собственная,
без оформления и резервирования в ekt.kz. Платёжные данные не запрашиваются.

## Планируемый основной сценарий

1. Покупатель отправляет запрос или список нужных товаров.
2. Ассистент ищет позиции в каталоге ekt.kz и показывает характеристики,
   цену и наличие.
3. Если товара нет, ассистент предлагает аналог и объясняет различия.
4. Перед добавлением показывается состав будущей корзины.
5. Корзина меняется только после явного подтверждения покупателя.
